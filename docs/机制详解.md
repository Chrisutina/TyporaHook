# 机制详解

> 面向想搞清楚"这东西到底怎么工作的"的人。结论先行：**不碰原厂字节码，只换加载器 + 在加载链上架拦截**。

## 1. app.asar 结构（Chromium Pickle）

Typora `resources\app.asar`（1.14.9，三文件重建版，398,849 B）解剖：

| 区段 | 偏移 | 内容 |
|---|---|---|
| size pickle | [0:8] | 固定头（len=4 / header=168） |
| header pickle | [8:16] | 含 JSON 长度（0xA0 = 160） |
| JSON 索引 | [16:176] | `files` 表：name → {size, offset} |
| 数据区 | [176…] | `launch.dist.js`（hook 10,070 B / 官方 1,383 B）→ `atom.compiled.dist.jsc`（388,352 B）→ `package.json`（251 B） |

校验链：176 + 10,070 + 388,352 + 251 = **398,849** ✅

## 2. 官方加载流程 vs Hook 流程

- **官方**：`launch.dist.js`（1,383 B）= 纯加载器，通过 `Module._extensions['.jsc']` 把 `atom.compiled.dist.jsc`（V8 字节码）挂进 Electron 主进程运行。
- **Hook（v2b）**：替换为 111 行的 `launch.dist.js` —— 在同一条链上先架拦截，**最后一行原样 `require("./atom.compiled.dist.jsc")`**。字节码一个 bit 未动。

## 4. 两个 v2 修复的来龙去脉

### 4.1 "用久了掉激活"（530s 二次校验）

- **取证**：插桩首个会话即抓到 `TIMER setTimeout delay=530469`，堆栈指向 `atom.compiled.dist.jsc:1:57155` —— 每次启动 ~0.3s 后调度、~530.5s 触发。
- **机制**：触发时按随机值分流——大概率走无害分支（renew / pass）；小概率走 `onUnfillLicense`（清许可证 → 应用内翻"未激活"，重启才恢复）。
- **历史样本**：8/26 20:00（0.49）、8/29 12:03（0.12）、9/11 08:40（0.08）均无害；9/11 22:49:38（0.95）踩中坏分支（0.3s 后 `SLicense restored` 救回注册表，但内存态救不回）。
- **修复**：拦截落在 [500k, 560k] ms 的定时器 → 空回调（其余定时器一律不动）。根治，且同样不碰字节码。

### 4.2 "本机任意进程可接管 Typora"（CDP 9223）

- **取证**：v1 hook 无条件 `appendSwitch('remote-debugging-port','9223')` → 任意本机进程可 attach、在渲染进程执行 JS、读任意文件（已实测复现）。
- **修复**：默认关闭 + `TYPORA_HOOK_DEBUG=1` 环境变量门控 + `removeSwitch` 外部参数防御。
- **顺带结案**："启动参数三件套"之谜——`--no-sandbox` 是 Typora 自己加的、`--allow-file-access-from-files` 是 Chromium 单实例转发机制携带的，均与破解无关；快捷方式/文件关联/计划任务全干净。
